# DevOps Lab 4 — IaC (Terraform + Ansible)

Lab 4 splits the Lab 1 single-host deployment across **two Ubuntu 24.04 VMs** provisioned by Terraform (via Multipass) and configured declaratively by Ansible. The Flask app, schema migration, and most of the deployment artefacts from Lab 1 are reused as inputs to Ansible templates.

## Architecture

```
                ┌───────────── VM1 (worker, lab4-worker) ─────────────┐    ┌── VM2 (db, lab4-db) ──┐
client :80  →   │  nginx :80  →  flask 127.0.0.1:5200                 │ →  │  MariaDB <VM-IP>:5200  │
                └─────────────────────────────────────────────────────┘    └────────────────────────┘
```

- **nginx** listens on `0.0.0.0:80` and only forwards documented business endpoints.
- **Flask** listens on `127.0.0.1:5200` (loopback-only — health endpoints are internal).
- **MariaDB** listens on the db-VM's private IP, port **5200** (per variant N = 16). UFW on VM2 allows TCP/5200 only from VM1.

## Repository layout (Lab 4 parts)

```
terraform/                  Provisioning — `terraform apply`
  versions.tf, variables.tf, main.tf, outputs.tf
  cloud-init/{worker,db}.yaml.tftpl
ansible/                    Configuration — `ansible-playbook site.yml`
  ansible.cfg, site.yml, group_vars/all.yml
  inventory.ini             ← generated by scripts/gen-inventory.sh
  roles/{common,db,app,nginx}/
scripts/gen-inventory.sh    Renders inventory from terraform output
```

## Prerequisites

On macOS (or any host that can run Multipass):

```bash
brew tap hashicorp/tap
brew install hashicorp/tap/terraform multipass ansible jq
ansible-galaxy collection install community.mysql community.general
ls ~/.ssh/id_ed25519.pub || ssh-keygen -t ed25519
```

`~/.ssh/id_ed25519.pub` is injected into both VMs by cloud-init for the `ansible` user. If you keep your key elsewhere, override `ssh_public_key_path` in Terraform.

## One-shot procedure

```bash
# 1. Provision two VMs (single command — acceptance criterion)
cd terraform
terraform init
terraform apply -auto-approve

# 2. Generate Ansible inventory from terraform outputs
cd ..
bash scripts/gen-inventory.sh

# 3. Smoke-check connectivity
ansible -i ansible/inventory.ini all -m ping

# 4. Configure everything (single command — acceptance criterion)
ansible-playbook -i ansible/inventory.ini ansible/site.yml
```

That's it. The app is now reachable at `http://<worker_ip>/`.

```bash
WORKER=$(terraform -chdir=terraform output -raw worker_ip)
curl -s "http://$WORKER/"
```

## Idempotency check

```bash
ansible-playbook -i ansible/inventory.ini ansible/site.yml --check --diff
```

Expect `changed=0` across all hosts (apart from intentional stateful checks).

## Variables you may want to override

`terraform/variables.tf` exposes VM sizes and the SSH key path. Override per-run:

```bash
terraform apply \
  -var 'ssh_public_key_path=~/.ssh/id_rsa.pub' \
  -var 'worker_memory=2G'
```

`ansible/group_vars/all.yml` holds app/DB credentials and the variant number `student_n=16`. Edit there — there is no separate `.env`.

## Verification (graded criteria)

```bash
WORKER=$(terraform -chdir=terraform output -raw worker_ip)
DB=$(terraform -chdir=terraform output -raw db_ip)

# Public endpoint (through nginx)
curl -s "http://$WORKER/"                                     # HTML page
curl -s -X POST -H 'Content-Type: application/json' \
     -d '{"title":"buy milk"}' "http://$WORKER/tasks"
curl -s -H 'Accept: application/json' "http://$WORKER/tasks"  # contains "buy milk"

# Health is internal-only — externally must 404
curl -i "http://$WORKER/health/alive"                         # 404
# …but reachable from inside the worker VM
multipass exec lab4-worker -- curl -s http://127.0.0.1:5200/health/alive   # OK
multipass exec lab4-worker -- curl -s http://127.0.0.1:5200/health/ready   # OK (DB reachable)

# DB isolation
nc -zv "$DB" 5200 || echo "PASS: DB unreachable from host (UFW)"
multipass exec lab4-worker -- bash -c "echo > /dev/tcp/$DB/5200 && echo PASS: worker can reach DB"

# Gradebook
multipass exec lab4-worker -- sudo cat /home/student/gradebook   # 16
multipass exec lab4-db     -- sudo cat /home/student/gradebook   # 16

# User access
ssh ansible@$WORKER 'sudo -n whoami'                          # root
ssh teacher@$WORKER 'whoami; sudo -k true'                    # password 12345678
ssh operator@$WORKER 'sudo -n systemctl restart mywebapp'     # OK
ssh operator@$WORKER 'sudo -n apt update' && echo BAD || echo "PASS: operator blocked"
```

## Teardown

```bash
cd terraform
terraform destroy -auto-approve
```

This deletes both Multipass VMs and the rendered cloud-init files. The Ansible inventory becomes stale; the next `terraform apply` + `gen-inventory.sh` refreshes it.

## How the lab acceptance criteria are met

| Criterion | Where |
| :--- | :--- |
| **Automation** — one `terraform apply`, one `ansible-playbook` | `terraform/main.tf`, `ansible/site.yml` |
| **Idempotency** — re-run yields 0 changes | All tasks use stateful modules (`apt`, `user`, `template`, `systemd`, `mysql_*`) |
| **Declarativeness** — no `shell` / `command` | Grep confirms: only `ansible.builtin.*` and `community.*` modules |
| **Distribution** — app on VM1 talks to DB on VM2 | `ansible/roles/app/templates/mywebapp.env.j2` injects `DB_HOST={{ db_ip }}` |
| **DB isolated** — external access blocked | `ansible/roles/db/tasks/main.yml` UFW rules — allow 5200 from worker only |
| **Users** — ansible / teacher / operator SSH works; operator sudo is narrow | `cloud-init/*.yaml.tftpl` + `roles/common` + `roles/app` + `templates/operator.sudoers.j2` |
| **Health checks** — `/health/alive` and `/health/ready` | Already in `app/main.py:65-77`; `/ready` opens a DB connection across VMs |
| **Templates with dynamic IPs** | `roles/app/templates/mywebapp.env.j2` and `roles/db/templates/50-server.cnf.j2` |

## Troubleshooting

| Symptom | Likely cause | Fix |
| :--- | :--- | :--- |
| `terraform apply` hangs at `multipass_instance.worker (creating)` | Multipass daemon not running | `multipass version` to start it (macOS), or `sudo snap start multipass` |
| Ansible task `wait_for_connection` times out | cloud-init still running | First boot can take 60–90 s; the play already waits 300 s |
| `community.mysql` module missing | Collection not installed | `ansible-galaxy collection install community.mysql community.general` |
| `MariaDB can't bind` to the VM IP | Interface naming quirk | The `50-server.cnf.j2` template uses `ansible_host`. Override with `bind-address = 0.0.0.0` (UFW still locks it down) |
| Worker can't reach DB on 5200 | UFW rule applied before MariaDB started | Re-run the playbook; the `db` role flushes handlers before grant tasks |
| operator can't `ssh` with password | SSH password auth disabled globally | `roles/app` installs `/etc/ssh/sshd_config.d/20-operator.conf` which re-enables PasswordAuthentication for `operator` only |
